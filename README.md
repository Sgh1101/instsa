# 인스타 다운로더

인스타그램 **게시물(사진·영상·여러 장 캐러셀)** 과 **릴스** 주소를 붙여 넣으면 미리보기를 보고 내려받을 수 있는 로컬 웹 앱입니다.

- 항목별 다운로드, 여러 개짜리 게시물은 **전체 zip** 다운로드
- 영상은 [yt-dlp](https://github.com/yt-dlp/yt-dlp), 사진은 가장 큰 해상도 원본을 직접 내려받음
- 서버는 기본적으로 내 컴퓨터(`127.0.0.1`)에서만 열림

## 실행

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py                                        # http://127.0.0.1:5000
```

`HOST`, `PORT` 환경 변수로 주소를 바꿀 수 있습니다. 인스타그램 쿠키를 쓰는 앱이라, `HOST`를 외부로 열면 **`APP_TOKEN`(비밀번호) 없이는 시작되지 않습니다.** 폰에서 쓰는 방법은 아래 [내 폰에서 나만 쓰기](#내-폰에서-나만-쓰기)를 보세요.

## 링크 자동 인식 (복붙하면 바로 뜸)

인스타그램에서 **링크 복사** → 이 앱을 열면 클립보드의 링크를 찾아 바로 조회하고, 화면 아래에 **저장 버튼**이 고정으로 뜹니다. "링크를 인식하면 바로 저장"을 켜면 버튼 없이 곧바로 저장됩니다. 같은 링크는 30분 동안 다시 자동 인식하지 않습니다(열 때마다 반복되지 않도록). 그 뒤에도 "붙여넣기" 버튼으로 언제든 받을 수 있어요.

**브라우저 정책 때문에 환경별로 다릅니다.** 웹 페이지는 보안상 클립보드를 마음대로 읽을 수 없습니다.

| 환경 | 동작 |
|---|---|
| Chrome / Edge (PC·안드로이드) | 처음 한 번 "클립보드 허용"을 누르면 이후 완전 자동 |
| iOS Safari, Firefox | 읽을 때마다 "붙여넣기 허용" 확인창이 뜸 (웹에서 막을 수 없음) |
| `http://` 로 접속(localhost 제외) | 클립보드 API 자체가 꺼져 자동 인식 불가 → **HTTPS 필요** |

### 인스타그램 앱에서 바로 보내기 (공유 → 이 앱)

복사 단계 없이 인스타그램의 **공유 → 이 앱**으로 보낼 수 있습니다. 이 앱을 홈 화면에 설치(PWA)하면 공유 대상 목록에 나타납니다.

- **안드로이드 Chrome**: HTTPS 주소(방법 B)에서 "앱 설치"하면 인스타그램 공유 시트에 "인스타 저장"이 뜹니다. `localhost`(Termux)로 설치한 경우에 뜨는지는 확인하지 못했습니다.
- **iOS**: 공유 대상 등록이 되는지는 확인하지 못했습니다(Chrome 문서가 보장하는 것은 안드로이드 Chrome 76 이상). 기대하지 말고 클립보드/붙여넣기 방식을 기본으로 쓰세요.
- 설치와 공유 대상 등록은 **HTTPS(또는 localhost)** 에서만 됩니다.
- 어떤 환경에서든 `https://내주소/?url=인스타링크` 로 열면 자동 조회됩니다.

## 내 폰에서 나만 쓰기 (안드로이드)

### 방법 A (기본): 앱(APK) 설치 — 서버·Termux 필요 없음

일반 앱처럼 설치해서 씁니다. 파이썬과 `yt-dlp`가 앱 안에 들어 있어 따로 서버를 돌릴 필요가 없습니다. (안드로이드 10 이상, 64비트 ARM 폰)

1. **APK 받기**: 이 저장소의 GitHub Actions에서 만든 `insta-save-debug-apk`를 받거나, 직접 빌드합니다(`cd android && ./gradlew assembleDebug` → `android/app/build/outputs/apk/debug/app-debug.apk`).
2. **설치**: 파일을 열고 "출처를 알 수 없는 앱 설치"를 허용합니다. 개인용 디버그 서명이라 Google Play 프로텍트가 "확인되지 않은 앱" 경고를 띄울 수 있습니다.
3. **쓰기** (두 가지 중 편한 쪽):
   - 인스타그램 **공유 → "인스타 저장"** 을 누르면 바로 조회됩니다.
   - 인스타그램에서 **링크 복사 → 앱 열기**: 앱이 클립보드에서 링크를 찾아 자동으로 조회합니다(안드로이드 12 이상은 "클립보드에서 붙여넣었습니다" 알림이 뜹니다).
4. **저장 버튼**을 누르면 **갤러리**에 저장됩니다(`Pictures/InstaSave`, `Movies/InstaSave`). 여러 장짜리는 각각 따로 저장됩니다. 저장 중에 앱을 나가도 계속됩니다.
5. **여러 개를 한꺼번에**: 인스타그램에서 링크를 여러 개 복사해 한 번에 붙여넣거나(메신저에서 받은 링크 모음도 됩니다), 입력칸/붙여넣기 버튼에 여러 링크를 넣으면 **'링크 N개를 찾았어요'** 묶음 카드가 뜹니다(한 번에 최대 30개). **'N개 모두 저장'** 을 누르면 백그라운드에서 순서대로 저장합니다.
   - 게시물 사이에 **3~6초 간격**을 둡니다(인스타그램 요청 제한을 덜 건드리려고).
   - **이미 저장한 게시물은 건너뜁니다**(인스타그램에 요청하지 않음). 다시 받으려면 "이미 저장한 게시물도 다시 받기"를 체크하세요.
   - 인스타그램이 **요청을 제한하거나 로그인을 요구하면 남은 항목은 멈추고** 요약을 알려 줍니다. 계속 시도하면 계정만 더 막히기 때문입니다.
   - "링크를 인식하면 바로 저장"을 켜 두어도 **묶음은 자동으로 시작하지 않고** 버튼을 눌러야 시작합니다.
6. **공유 → "바로 저장" (앱 화면을 열지 않음)**: 공유 시트에는 "인스타 저장"과 **"바로 저장 (인스타 저장)"** 두 항목이 뜹니다. "바로 저장"을 누르면 앱 화면을 열지 않고 백그라운드에서 저장만 시작해서 **인스타그램 화면에 그대로 머뭅니다.** 끝나면 알림으로 알려 줍니다(누르면 저장한 파일이 열림). 이미 받은 게시물은 건너뛰고, 링크가 여러 개 들어 있으면 묶음(최대 30개)으로 처리합니다.
   - **새 게시물을 받는 가장 안전한 흐름**: 인스타그램에서 그 계정의 **🔔(게시물 알림)** 을 켜 둔다 → 새 글 알림이 오면 게시물을 연다 → **공유 → 바로 저장**.
   - **자동 감시(예약해 두면 새 글을 알아서 받기)는 만들지 않았습니다.** 주기적으로 프로필을 조회해야 하는데, 그 방법이 인스타그램 비공개 API뿐이고 로그인한 계정이 자동화로 보여 제한될 위험이 크기 때문입니다.
7. **최근 저장 / 저장한 프로필**: 저장한 게시물은 화면 아래 **'최근 저장'**(미리보기·계정·시간, 누르면 갤러리에서 열림)에, 그 계정은 **'최근 저장한 프로필'** 에 올라옵니다. 프로필을 누르면 **그 계정에서 저장한 게시물**이 모아 보이고, 거기서 두 가지로 더 받을 수 있습니다.
   - **앱 안에서 둘러보기**(앱 전용): 앱 안에서 실제 인스타그램 화면(WebView)이 열립니다. 사람이 직접 넘겨 보다가 게시물/릴스를 열면 **"이 게시물 저장"** 버튼이 떠서, 누를 때마다 그 게시물 하나를 백그라운드로 저장합니다(이미 받은 것은 "다시 저장"). 둘러보기 화면에서 로그인하면 그 로그인이 저장에도 쓰입니다.
   - **인스타그램에서 열기**: 인스타그램 앱으로 프로필을 엽니다. 게시물을 공유하면 이 앱으로 들어옵니다.
   앱이 계정의 게시물 목록을 **대신 불러오지 않습니다**(자동 조회 없음). 목록은 사람이 보는 화면에서 사람이 넘기고, 저장도 한 번 누를 때 한 개씩이라 '공유 → 바로 저장'과 같은 요청입니다. ✕는 저장 기록(미리보기 포함)만 지웁니다(갤러리의 파일은 그대로).
8. **로그인**: 화면 맨 아래 **'인스타그램 로그인 설정' → '인스타그램에 로그인'** 을 누르면 인스타그램 로그인 화면이 열리고, 로그인하면 앱이 로그인 쿠키만 가져가 저장합니다(비밀번호는 앱이 보지 않음). 사실상 필수입니다.

**문제가 생기면 (저장이 안 될 때)**
- 실패하면 화면에 **빨간 오류 카드**가 뜨고 닫을 때까지 남습니다(5초 만에 사라지는 알림이 아닙니다). **"자세히"** 를 누르면 인스타그램이나 앱이 돌려준 원문 오류가 보입니다.
- **"진단하기"**(또는 설정의 **"문제 진단"**)를 누르면 앱 안의 파이썬 버전, `yt-dlp`·`requests`·인증서 상태, 저장 폴더 쓰기 여부, 인스타그램 접속(홈페이지 요청 1번), 로그인 쿠키 유무, 문제가 난 게시물 조회 시험 1번, 최근 오류 10건을 한 번에 점검해서 글로 보여 줍니다.
- **"복사"** 로 오류나 진단 결과를 복사해서 그대로 전달하면 원인을 좁힐 수 있습니다. 쿠키 값이나 비밀번호는 포함되지 않습니다.
- 가장 흔한 원인은 **로그인 없이 쓰다 인스타그램의 익명 요청 제한에 걸린 것**입니다. 화면 맨 아래 **'인스타그램에 로그인'** 을 먼저 해 보세요.

**한계**
- **프로필 주소를 넣어 게시물·릴스를 자동으로 전부 불러오는 기능은 없습니다.** `yt-dlp`의 프로필 추출기가 소스에서 `_WORKING = False`(동작 안 함)로 표시되어 있고, 대안은 인스타그램의 비공개 내부 API를 직접 호출하는 것인데 약관 위반 소지와 계정 제한 위험이 크고 쉽게 깨집니다. 그래서 만들지 않았습니다. 대신 위의 "링크 묶음 저장"과 "저장한 프로필 → 인스타그램에서 공유"를 쓰세요. **내 계정**의 게시물이라면 인스타그램의 공식 "내 정보 다운로드"가 가장 확실합니다.
- `yt-dlp`가 앱에 **고정**되어 있습니다(2026.10.21). 인스타그램이 바뀌어 다운로드가 깨지면 **앱을 다시 빌드해 다시 설치**해야 합니다. (앱 안 업데이트 기능은 아직 없습니다.)
- 안드로이드에는 ffmpeg이 없어서, 영상/음성이 분리되어 있는 영상은 받지 못할 수 있습니다. 인스타그램은 보통 소리가 들어 있는 단일 mp4도 함께 제공해서 대부분 받아지지만, 일부 릴스에서는 실패할 수 있습니다.
- 저장은 **백그라운드(알림이 뜨는 포그라운드 서비스)** 에서 진행되어, 앱을 나가거나 화면을 꺼도 계속됩니다. 앱이 화면에 없을 때 끝나면 알림이 뜨고, 누르면 저장한 사진/영상이 열립니다. 여러 개를 연달아 저장하면 한 번에 하나씩 순서대로 처리합니다.
- 안드로이드 13 이상은 처음 저장할 때 **알림 권한**을 한 번 묻습니다. 거절해도 저장은 되지만 진행/완료 알림이 보이지 않을 수 있습니다.
- 인스타그램이 앱 내 브라우저의 로그인을 막는 경우가 있을 수 있습니다(확인하지 못함).

### 다른 방법 (웹 앱으로 쓰기)

이 앱은 **설치형 웹 앱(PWA)** 입니다. 홈 화면에 아이콘이 생기고 주소창 없는 앱 화면으로 열리지만, 앱스토어 앱(APK)은 아닙니다. 서버(이 코드)가 어딘가에서 돌고, 폰의 Chrome이 거기에 접속하는 구조입니다.

#### 방법 B: 폰 하나로 — Termux

컴퓨터가 필요 없습니다. 폰 안에서 서버를 돌리고(`localhost`, 기기 밖으로는 열리지 않음) Chrome으로 접속합니다. 폰 밖에서 접근할 수 없으니 HTTPS도 비밀번호도 필요 없습니다. 단, Termux가 실행 중이어야 합니다.

1. **Termux 설치**: [F-Droid](https://f-droid.org/packages/com.termux/) 또는 [GitHub 릴리스](https://github.com/termux/termux-app/releases)에서 받으세요. **Play 스토어 버전은 공식 배포가 아니라 구버전**입니다([공식 안내](https://github.com/termux/termux-app/discussions/4000)). 배포처를 섞으면 업데이트가 안 되니 한 곳만 쓰세요.
2. **Termux에서 설치** (한 번만):
   ```bash
   pkg install -y git
   git clone -b ccr-ee153283-acrbmz https://github.com/Sgh1101/instsa && cd instsa
   bash termux/setup.sh      # python, ffmpeg, 의존성 설치
   ```
   저장소가 비공개라면 GitHub 로그인(토큰)이 필요합니다.
3. **켜기**: `bash termux/start.sh` — 서버를 켜고 Chrome으로 `http://localhost:5000`을 엽니다. (끄기: `bash termux/stop.sh`)
4. **앱으로 설치**: Chrome 메뉴(⋮) → **앱 설치 / 홈 화면에 추가**.
5. **로그인 쿠키 등록**: 화면 맨 아래 **'인스타그램 로그인 설정'** (아래 [쿠키](#인스타그램-로그인-쿠키) 참고). 사실상 필수입니다.
6. **쓰기**: 인스타그램 → 공유 → **링크 복사** → 앱 열기. 처음 한 번 "클립보드 허용"을 누르면 이후 자동으로 인식합니다.

폰을 재부팅하거나 Termux가 종료되면 3번을 다시 실행하세요. 화면이 꺼져도 멈추지 않게 `start.sh`가 wake-lock을 겁니다. 기기에 따라 설정에서 Termux의 배터리 최적화를 꺼 줘야 할 수 있습니다.
업데이트: `git pull && .venv/bin/pip install -U yt-dlp` (인스타그램이 바뀌면 yt-dlp 업데이트로 대부분 해결됩니다).

> `PORT`를 바꿀 때는 Chrome이 차단하는 포트(5060, 5061, 6000, 6665~6669 등)를 피하세요. `ERR_UNSAFE_PORT`가 납니다.

**한계**: localhost로 설치한 앱이 인스타그램의 **공유 목록에 나타나는지는 확인하지 못했습니다.** 위 6번(링크 복사 → 앱 열기)을 기본으로 생각하세요.

#### 방법 C: 항상 켜 둔 컴퓨터가 있다면 — Docker + Tailscale

폰에서 `https://…ts.net` 주소로 접속하므로 HTTPS 설치와 공유 목록 등록(안드로이드 Chrome)이 확실하게 됩니다. [Tailscale](https://tailscale.com/)은 내 기기끼리만 연결되는 사설망이라 서버가 인터넷에 공개되지 않습니다. 집 인터넷 IP는 클라우드 서버 IP보다 인스타그램 제한이 덜한 편으로 알려져 있습니다(직접 비교하지는 못했습니다).

1. **비밀번호 만들기**: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`
2. **서버 켜기** (상시 켜 둘 컴퓨터에서):
   ```bash
   APP_TOKEN='위에서 만든 비밀번호' docker compose up -d --build
   ```
   포트는 그 컴퓨터(127.0.0.1)에만 열립니다. `APP_TOKEN`이 없으면 시작되지 않습니다.
3. **Tailscale 설치**: 그 컴퓨터와 폰 양쪽에 설치하고 같은 계정으로 로그인합니다. MagicDNS와 HTTPS 인증서가 켜져 있어야 합니다(공식 문서 기준 새 tailnet은 기본으로 켜져 있고, 처음 쓸 때 안내가 나옵니다).
4. **HTTPS로 노출**: 그 컴퓨터에서 `tailscale serve --bg 5000` → `tailscale serve status`에 나온 `https://기기이름.tailnet이름.ts.net` 주소가 내 주소입니다. (Tailscale 1.52에서 명령이 바뀌었으니 안 되면 `tailscale serve --help`. [공식 문서](https://tailscale.com/docs/reference/tailscale-cli/serve))
5. **폰에서**: 그 주소를 열고 비밀번호 입력 → Chrome **앱 설치**. 설치하면 인스타그램의 공유 목록에 "인스타 저장"이 나타납니다.
6. 로그인은 90일 유지됩니다. `APP_TOKEN`을 바꾸면 모든 기기에서 로그아웃됩니다.

업데이트: `docker compose build --pull --no-cache && docker compose up -d`. 쿠키는 `igdl-data` 볼륨에 저장되어 유지됩니다.

## 인스타그램 로그인 쿠키

인스타그램은 로그인하지 않은(익명) 접근에 횟수 한도를 둡니다. 몇 번 쓰면 이런 오류가 납니다(실제로 확인했습니다).

> You have exceeded the rate-limit for accessing posts anonymously.

그러면 앱이 쿠키 등록을 안내하고 설정 칸을 자동으로 엽니다. 개인용으로 꾸준히 쓰려면 등록하세요. 내가 팔로우 중인 비공개 계정 게시물도 받을 수 있게 됩니다.

### 앱에서 등록 (폰에서 쓸 때 권장)

화면 맨 아래 **'인스타그램 로그인 설정'** 을 펼치세요.

1. PC 브라우저에서 인스타그램에 로그인
2. **F12 → Application(애플리케이션) → Cookies → instagram.com**
3. **`sessionid`** 의 값(Value)을 복사 → 앱의 입력칸에 붙여넣고 저장 (폰으로는 메신저 "나에게 보내기"로 전달)

`sessionid` 하나면 됩니다(yt-dlp는 이 쿠키로 로그인 여부를 판단합니다). `csrftoken`은 선택입니다. 값은 서버(폰 안의 Termux, 또는 Docker 볼륨)에 `cookies.txt`로 저장되고(권한 600), **화면이나 API로 다시 돌려주지 않습니다.** 폰만으로 쿠키를 꺼내는 방법은 확인하지 못했습니다.

### PC에서 직접 실행할 때

```bash
IG_COOKIES_FROM_BROWSER=chrome python app.py        # 브라우저에 로그인된 쿠키를 직접 사용 (firefox, edge, safari 등도 가능)
IG_COOKIES_FILE=/path/to/cookies.txt python app.py  # Netscape 형식 cookies.txt
```

### 주의

- 쿠키는 **계정 로그인 권한과 같습니다.** 반드시 **부계정**을 쓰고, 다른 사람에게 보내거나 저장소에 올리지 마세요(`cookies*.txt`는 `.gitignore`에 포함). 의심되면 인스타그램에서 로그아웃하면 그 쿠키는 무효가 됩니다.
- 자동화된 접근은 인스타그램이 계정을 일시 제한할 수 있습니다. 짧은 시간에 많은 요청을 보내지 마세요.

## 테스트

```bash
pip install -r requirements-dev.txt
python -m pytest
```

브라우저로 화면을 검증하는 시나리오는 이 저장소에 포함되어 있지 않습니다(개발 중 임시로 Playwright로 돌렸음).

APK 빌드에는 JDK 17+와 Android SDK(`ANDROID_HOME`)가 필요합니다.

테스트는 네트워크 없이 동작합니다. 가짜 Instagram 추출기와 로컬 HTTP 서버로 yt-dlp의 실제 추출·다운로드 경로(사진 전용 게시물, 영상, 혼합 캐러셀 포함)를 통과시킵니다.

## 알려진 한계

- **인스타그램이 내부 구조를 바꾸면 깨질 수 있습니다.** 대부분 yt-dlp 업데이트로 해결됩니다: `pip install -U yt-dlp`
- 사진 전용 게시물은 yt-dlp가 직접 지원하지 않아, 추출된 이미지 후보 중 가장 큰 것을 받습니다. 이 방식도 인스타그램 응답 형식에 의존합니다.
- 다운로드는 서버가 임시 폴더에 받은 뒤 브라우저로 전송합니다(전송이 끝나거나 연결이 끊기면 삭제). 매우 큰 영상은 시간이 걸립니다.
- 한 번에 한 게시물만 처리합니다. 대량 수집용이 아닙니다.
